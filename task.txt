Задача:
Создать лёгкую локальную GUI-оболочку для текущего Codex orchestrator без переписывания backend.

Цель:
Сделать быстрый удобный интерфейс вместо ручной работы через notepad + PowerShell.

Технический подход:
- Использовать Python 3 и Tkinter
- Сделать один файл: tools/upgr_agent_gui.py
- Не использовать Electron
- Не менять существующий backend pipeline без крайней необходимости
- Использовать уже существующие:
  - auto-codex.ps1
  - task.txt
  - git
  - codex exec

Функции GUI:
1. Большое текстовое поле для ввода ТЗ
2. Кнопка Run:
   - сохраняет текст в task.txt
   - запускает .\auto-codex.ps1
3. Кнопка Stop:
   - останавливает текущий процесс, если он запущен
4. Блок статуса:
   - текущая ветка git
   - clean/dirty статус repo
5. Область live-лога:
   - показывает stdout/stderr во время выполнения
6. Кнопка Open Logs:
   - открывает папку artifacts/agent-logs если она есть
7. Кнопка Open Project:
   - открывает корень проекта в проводнике
8. При старте GUI:
   - если task.txt существует, подгружает его содержимое в поле ввода

UX требования:
- Тёмная тема
- Аккуратный интерфейс
- Без визуального мусора
- Удобно для постоянного использования
- Окно должно быть нормального рабочего размера, не слишком маленьким

Ограничения:
- Разрешено менять только:
  - tools/upgr_agent_gui.py
  - при необходимости создать tools/__init__.py
- Не менять:
  - app/**
  - components/**
  - public/**
  - prisma/**
  - route-entry файлы Next.js
- Не ломать текущий orchestrator
- Если для работы GUI нужен минимальный вспомогательный файл, сначала держать решение максимально простым и в одном Python-файле

Проверка:
1. GUI запускается локально командой:
   python tools/upgr_agent_gui.py
2. Текст из task input сохраняется в task.txt
3. Run реально запускает auto-codex.ps1
4. Лог отображается в окне
5. Можно остановить процесс
6. Статус ветки и git состояния читается корректно

После выполнения:
- Остановиться
- Кратко указать, как запускать GUI
